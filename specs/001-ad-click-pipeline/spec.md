# Feature Specification: 광고 클릭 수집·집계·준실시간 서빙 파이프라인

**Feature Branch**: `001-ad-click-pipeline`

**Created**: 2026-11-15

**Status**: Draft

**Input**: User description: "광고 클릭 이벤트를 수집해서 유실 / 중복없이 저장하고, 집계하여 광고주에게
준실시간 서빙 가능한 전체 흐름." (도메인 모델: "광고 클릭 집계 · 경량 도메인 ERD" 문서)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 클릭을 유실·중복 없이 측정·저장 (Priority: P1)

광고를 본 사용자가 광고를 클릭하면, 시스템은 그 클릭을 측정해 고유한 클릭 식별자를 발급하고
사용자를 광고 랜딩 페이지로 보낸다. 측정된 클릭은 하나도 잃지 않고, 같은 클릭이 여러 번
전달되어도 한 번만 저장된다. 광고 노출도 같은 방식으로 기록되어 이후 판정의 기준이 된다.

**Why this priority**: 이후의 판정·집계·서빙은 모두 저장된 클릭을 근거로 한다. 여기서 잃거나
중복되면 광고주가 보는 숫자가 틀린다.

**Independent Test**: 클릭을 대량으로 보내면서 중복 전송과 일시 장애를 섞은 뒤, 저장된 클릭 수가
보낸 고유 클릭 수와 정확히 같은지 대조해 검증한다. 광고주 화면 없이도 "모든 클릭이 정확히 한 번
기록된다"는 가치를 단독으로 보여준다.

**Acceptance Scenarios**:

1. **Given** 등록된 광고와 그 노출, **When** 사용자가 광고를 클릭하면, **Then** 클릭이 고유 식별자와
   측정 시각과 함께 저장되고 사용자는 랜딩 페이지로 이동한다.
2. **Given** 이미 저장된 클릭, **When** 같은 클릭 식별자의 클릭이 다시 전달되면, **Then** 저장된 클릭
   수는 변하지 않는다.
3. **Given** 저장 단계가 일시적으로 실패한 상황, **When** 장애가 복구되면, **Then** 실패 동안 측정된
   클릭이 모두 저장되어 있다.
4. **Given** 형식이 잘못된 클릭 이벤트, **When** 수신되면, **Then** 버려지지 않고 격리 보관되어 나중에
   확인할 수 있다.

### User Story 2 - 클릭 유효성 판정과 일별 확정 리포트 (Priority: P2)

저장된 클릭마다 판정 규칙(노출 없음, 오래된 노출, 짧은 간격 재클릭, 비인간 트래픽)을 적용해
유효/무효와 무효 사유를 정한다. 광고별·일별로 유효 클릭과 무효 클릭 수를 집계하고, 하루가
끝나고 늦게 도착하는 클릭까지 반영한 뒤 그날의 수치를 확정한다.

**Why this priority**: 광고주에게 내보이는 숫자의 기준이 된다. 수집(P1)이 있어야 의미가 있고,
서빙(P3)은 이 결과를 보여준다.

**Independent Test**: 판정 사유별로 준비한 클릭 묶음을 넣고, 각 클릭의 판정과 일별 유효/무효 합계가
기대값과 일치하는지, 유효 + 무효 = 그날 측정된 클릭 총수가 성립하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 노출 없이 들어온 클릭, **When** 판정하면, **Then** 무효(노출 없음)로 판정된다.
2. **Given** 노출 후 유효기간이 지나서 들어온 클릭, **When** 판정하면, **Then** 무효(오래된 노출)로
   판정된다.
3. **Given** 같은 노출에서 재클릭 간격보다 짧게 이어진 두 번째 클릭, **When** 판정하면, **Then**
   무효(중복 클릭)로 판정된다.
4. **Given** 봇 목록에 있는 기기 정보 또는 내부 IP의 클릭, **When** 판정하면, **Then** 무효(비인간)로
   판정된다.
5. **Given** 판정 규칙이 새 버전으로 바뀐 상황, **When** 재판정하면, **Then** 새 버전의 판정이 추가되고
   이전 버전의 판정은 그대로 남는다.
6. **Given** 확정된 날짜의 리포트, **When** 그날에 속하는 클릭이 늦게 도착하면, **Then** 기존 확정
   수치는 바뀌지 않고 보정 사유가 붙은 새 개정본이 만들어진다.

### User Story 3 - 광고주가 자기 광고 성과를 준실시간으로 조회 (Priority: P3)

광고주는 조회 API로 자기 광고의 유효·무효 클릭 수를 조회한다. 클릭은 1분 단위로 집계되어 측정 후
몇 분 안에 조회에 반영되고, 광고주는 최근 M분 동안의 광고별 클릭 수와 클릭이 가장 많은 광고 상위
N개를 볼 수 있다. 지난 날짜의 일별 수치는 확정치(최신 개정본)로 보인다. 광고주는 다른 광고주의
데이터를 볼 수 없다.

**Why this priority**: 사용자가 요청한 최종 가치지만, 수집(P1)과 판정·집계(P2) 결과를 보여주는
단계이므로 마지막에 놓는다.

**Independent Test**: 클릭을 흘려보내면서 광고주로 조회해, 정해진 지연 안에 수치가 반영되는지,
잠정/확정 표시가 맞는지, 다른 광고주의 광고가 보이지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 클릭이 계속 들어오는 광고, **When** 광고주가 최근 M분의 클릭 수를 조회하면, **Then**
   신선도 목표(SC-009) 이내에 측정된 클릭까지 1분 단위로 반영된 잠정치가 "잠정"으로 표시되어 보인다.
2. **Given** 광고주의 여러 광고, **When** 최근 M분 동안 클릭이 가장 많은 상위 N개 광고를 조회하면,
   **Then** 유효 클릭 수 기준으로 정렬된 목록이 나온다.
3. **Given** 확정된 지난 날짜, **When** 광고주가 일별 수치를 조회하면, **Then** 최신 개정본의 수치가
   "확정"으로 보인다.
4. **Given** 광고주 A, **When** 광고주 B의 광고를 조회하려 하면, **Then** 거부된다.
5. **Given** 광고주의 시간대, **When** 일별 수치를 조회하면, **Then** 날짜 경계는 그 광고주의
   시간대를 따른다.

### User Story 4 - 시스템을 설명하는 실시간 시각화 (포트폴리오 데모) (Priority: P4)

프로젝트 오너가 자기 컴퓨터에서 시스템을 띄우면, 포트폴리오를 보는 사람(면접관, 채용 담당자, 다른
개발자)은 시각화 화면에서 이 시스템이 어떻게 동작하는지 실시간으로 본다. 합성 클릭이 수집 → 저장 → 판정 → 집계 → 서빙으로 흘러가는 모습과 단계별
처리량·지연·중복 제거·격리 수가 보이고, 각 단계에 "왜 이렇게 설계했는지"(멱등 키로 중복 제거, 늦은
도착 유예, 사실과 판정 분리, 잠정→확정) 짧은 설명이 붙는다. 보는 사람은 미리 준비된 시나리오(중복
전송 폭주, 늦게 도착한 클릭, 한 단계 장애)를 직접 실행해, 그 상황에서도 숫자가 맞는다는 것을 눈으로
확인한다.

**Why this priority**: 이 프로젝트를 포트폴리오로 보여주는 창구다. 유실·중복 없음 같은 보장은 코드만으로는
전달하기 어려워서, 직접 눌러 보고 결과를 확인하게 한다. P1~P3가 동작해야 보여줄 것이 생기므로
마지막에 놓는다.

**Independent Test**: 처음 보는 사람이 설명 없이 화면만 보고 데이터가 어느 단계를 거치는지 말할 수 있는지,
각 시나리오를 실행했을 때 화면에 상황(중복 제거 수 증가, 적체와 회복, 개정본 생성)이 나타나고 대조식이
끝까지 맞는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로컬에서 띄운 데모 환경에 합성 클릭이 계속 흐르는 상황, **When** 화면을 열면, **Then**
   로그인 없이 단계별 흐름과 처리량·지연·중복 제거 수·격리 수가 보이고 몇 초 간격으로 갱신된다.
2. **Given** 시각화 화면, **When** 보는 사람이 단계를 가리키거나 누르면, **Then** 그 단계가 하는 일과 설계
   이유가 짧게 설명된다.
3. **Given** 시각화 화면, **When** 보는 사람이 "중복 전송 폭주" 시나리오를 실행하면, **Then** 중복 제거 수가
   늘어나는 것이 보이고 반영된 클릭 수는 고유 클릭 수와 같게 유지된다.
4. **Given** 시각화 화면, **When** 보는 사람이 "단계 장애" 시나리오를 실행하면, **Then** 그 단계에 적체가 쌓이는
   것이 보이고, 자동 복구 후 적체가 줄어들며 유실 0건이 표시된다.
5. **Given** 시각화 화면, **When** 보는 사람이 "늦게 도착한 클릭" 시나리오를 실행하면, **Then** 준실시간 집계와
   일별 리포트에 어떻게 반영되는지(확정 후라면 새 개정본) 보인다.
6. **Given** 어떤 시나리오가 진행 중, **When** 화면을 보면, **Then** "수신 = 반영 + 중복 제거 + 격리"
   대조식이 실시간으로 표시되고 끝까지 성립한다.

---

### Edge Cases

- 클릭이 그 클릭의 노출보다 먼저 도착하면, 노출 없음으로 잘못 판정되지 않도록 노출 도착을 기다리는
  유예 시간 안에서는 판정을 미룬다.
- 같은 노출의 클릭들이 측정 순서와 다르게 도착하면, 중복 클릭 판정은 도착 순서가 아니라 측정 시각
  순서로 한다.
- 클릭이 존재하지 않는 노출을 가리키면, 유예 시간이 지난 뒤 노출 없음으로 판정한다.
- 판정 전 클릭이 남아 있는 잠정치에서는, 판정 대기 수를 함께 보여 유효 + 무효 + 판정 대기 =
  측정된 클릭 총수가 성립하게 한다.
- 확정 이후 도착한 늦은 클릭은 원래 측정 날짜에 귀속되고, 새 개정본으로만 반영된다.
- 광고주의 시간대가 바뀌면, 이미 확정된 과거 리포트의 날짜 경계는 바뀌지 않는다.
- 재시도 한도를 넘긴 이벤트는 격리 보관되고, 격리된 수가 0이 아니면 운영자가 알 수 있다.
- 1분 집계 구간이 닫힌 뒤(짧은 유예 시간 이후) 도착한 클릭은 준실시간 집계에는 빠질 수 있지만, 일별
  확정 리포트에는 반드시 반영된다.
- 시각화 화면을 여러 탭으로 열거나 오래 열어 두어도 파이프라인의 처리량과 지연에 영향을 주지 않는다.
- 시나리오가 진행 중일 때 다른 시나리오를 누르면 실행되지 않고, 진행 중인 시나리오가 보인다.

## Requirements *(mandatory)*

### Functional Requirements

**수집·저장 (US1)**

- **FR-001**: 시스템은 클릭을 측정하는 시점에 전역적으로 고유한 클릭 식별자를 발급하고 측정 시각을
  기록해야 한다(MUST).
- **FR-002**: 시스템은 클릭을 측정한 뒤 사용자를 해당 광고의 랜딩 페이지로 보내야 한다(MUST).
- **FR-003**: 시스템은 클릭이 내구성 있게 저장되기 전에는 저장 성공으로 취급해서는 안 된다(MUST NOT).
- **FR-004**: 시스템은 같은 클릭 식별자를 가진 클릭을 한 번만 저장해야 한다(MUST). 중복 판단 기간은
  제한 없음(클릭 식별자는 영구히 고유)으로 한다.
- **FR-005**: 시스템은 광고 노출을 고유 노출 식별자, 광고, 노출 시각과 함께 기록해야 한다(MUST).
- **FR-006**: 시스템은 처리에 실패한 이벤트를 재시도하고, 재시도 한도를 넘으면 버리지 않고 격리
  보관해야 한다(MUST).
- **FR-007**: 시스템은 약속된 이벤트 형식에 맞지 않는 이벤트를 격리 보관해야 한다(MUST). 이벤트 형식은
  버전으로 관리되며, 하위 호환을 깨는 변경은 새 버전으로만 한다.
- **FR-008**: 저장된 노출과 클릭은 수정하거나 삭제하지 않는다(MUST, append-only).
- **FR-009**: IP와 기기 정보(user agent)는 개인정보 필드로 표시해야 한다(MUST). 현재는 테스트·합성
  데이터만 다루므로 원본 값을 저장한다.

**판정·집계 (US2)**

- **FR-010**: 시스템은 각 클릭을 판정 규칙 버전마다 정확히 한 번 판정해 유효/무효와 무효 사유를
  남겨야 한다(MUST).
- **FR-011**: 판정 규칙은 다음 순서로 평가해야 한다(MUST): 노출 없음 → 오래된 노출(클릭 시각 − 노출
  시각이 유효기간 초과) → 중복 클릭(같은 노출의 직전 클릭과의 간격이 재클릭 간격 미만) → 비인간(봇
  기기 정보 목록 일치 또는 내부 IP) → 그 외 유효.
- **FR-012**: 유효기간·재클릭 간격·봇 목록 같은 파라미터는 판정 규칙 버전에 속해야 하며, 규칙이 바뀌면
  새 버전으로 다시 판정하고 이전 판정은 보존해야 한다(MUST).
- **FR-013**: 시스템은 노출이 늦게 도착할 수 있음을 고려해, 클릭 측정 후 유예 시간이 지나기 전에는
  노출 없음 판정을 확정해서는 안 된다(MUST NOT).
- **FR-014**: 시스템은 광고별·일별로 유효 클릭 수와 무효 클릭 수(사유별 포함)를 집계해야 한다(MUST).
  날짜 경계는 광고주의 시간대를 따르고, 클릭은 측정 시각으로 날짜에 귀속된다.
- **FR-015**: 확정 리포트에서는 유효 + 무효 = 그날 측정된 클릭 총수가 성립해야 하고, 잠정치에서는
  유효 + 무효 + 판정 대기 = 측정된 클릭 총수가 성립해야 한다(MUST).
- **FR-016**: 일별 리포트는 날짜가 끝나고 늦은 도착 유예 시간이 지나면 확정해야 한다(MUST). 확정 전
  잠정치는 덮어쓸 수 있고, 확정치는 바꿀 수 없다.
- **FR-017**: 확정 후 보정은 개정 번호를 1 올리고 보정 사유를 가진 새 확정본으로만 해야 한다(MUST).

**서빙 (US3)**

- **FR-018**: 광고주는 자기 광고의 일별 유효·무효 클릭 수를 조회할 수 있어야 한다(MUST). 지난 날짜는
  최신 개정본의 확정치를, 오늘은 잠정치를 보여주고, 잠정/확정 여부를 함께 표시한다.
- **FR-019**: 광고주는 다른 광고주의 광고 데이터를 조회할 수 없어야 한다(MUST).
- **FR-020**: 시스템은 클릭을 광고별 1분 단위 구간으로 집계해야 하며(MUST), 광고주는 최근 M분(1~1440분)
  동안의 광고별 유효·무효 클릭 수를 조회할 수 있어야 한다. 1분 집계는 구간이 끝난 뒤 짧은 유예 시간
  동안 늦은 클릭을 기다린 다음 닫는다.
- **FR-021**: 광고주는 최근 M분 동안 유효 클릭이 가장 많은 자기 광고 상위 N개(N ≤ 100)를 조회할 수
  있어야 한다(MUST).
- **FR-022**: 광고주에게 서빙하는 수단은 조회 API뿐이다. 광고주용 화면은 이번 범위 밖이다.

**운영·관측 (전 단계)**

- **FR-023**: 시스템은 단계별로 수신 수, 저장 성공 수, 재시도 수, 격리 수, 중복 제거 수, 측정부터
  조회 반영까지의 지연을 기록해 대조할 수 있어야 한다(MUST).
- **FR-024**: 저장된 데이터에서 1분 집계와 일별 리포트를 언제든 다시 만들 수 있어야 하며, 다시 만들어도
  같은 입력이면 같은 결과가 나와야 한다(MUST).

**시스템 설명 시각화 (US4)**

- **FR-025**: 시스템은 로컬 데모 환경에서 로그인 없이 볼 수 있는 시각화 화면을 제공해야 한다(MUST). 화면은 수집 →
  저장 → 판정 → 집계 → 서빙 단계를 흐름으로 보여주고, 단계마다 초당 처리량, 지연, 적체량을 표시한다.
- **FR-026**: 시각화 화면은 중복 제거 수, 격리 수, 유효/무효 비율, 무효 사유별 분포를 표시해야 한다(MUST).
- **FR-027**: 시각화 화면은 "수신 = 반영 + 중복 제거 + 격리" 대조 결과를 실시간으로 표시하고, 맞지 않으면
  경고해야 한다(MUST).
- **FR-028**: 시각화 화면은 단계마다 하는 일과 설계 이유(중복 제거, 늦은 도착 유예, 사실·판정 분리,
  잠정→확정)를 짧게 설명해야 한다(MUST).
- **FR-029**: 보는 사람은 미리 정해진 데모 시나리오(중복 전송 폭주, 늦게 도착한 클릭, 단계 장애)를 실행할 수
  있어야 한다(MUST). 시나리오는 한 번에 하나만 돌고, 정해진 시간이 지나면 정상 상태로 자동 복구된다.
- **FR-030**: 데모 환경은 합성 데이터 생성기로 클릭을 계속 흘려야 하며(MUST), 아무도 조작하지 않아도 화면에
  움직임이 보이게 한다.
- **FR-031**: 시각화 화면의 수치는 FR-023의 지표에서 나와야 하며, 화면을 보는 것이 파이프라인 처리에
  영향을 주어서는 안 된다(MUST NOT).
- **FR-032**: 시각화 화면에서는 시나리오 실행 외에 데이터나 설정을 바꿀 수 없어야 한다(MUST).
- **FR-033**: 데모 환경 전체(파이프라인, 데이터 생성기, 시각화 화면)는 명령 하나로 로컬에서 띄우고 내릴
  수 있어야 한다(MUST).

### Key Entities *(include if feature involves data)*

- **광고주(Advertiser)**: 리포트의 소유자. 시간대를 가지며, 이 시간대가 일별 리포트의 날짜 경계를 정한다.
- **광고(Ad)**: 클릭이 귀속되는 단위이자 리포트의 행. 하나의 광고주에 속한다.
- **노출(Impression)**: 광고가 사용자에게 보인 사실. 광고와 노출 시각을 가지며 수정되지 않는다.
  클릭의 출처와 유효기간 판정의 기준이다.
- **클릭(Click)**: 측정된 클릭 그 자체. 클릭 식별자(멱등 키), 광고, 노출(없을 수 있음), IP, 기기 정보,
  측정 시각을 가지며 수정되지 않는다. 노출이 있으면 클릭의 광고는 노출의 광고와 같다.
- **클릭 판정(Click Verdict)**: 클릭 하나에 대한 판정 규칙 버전별 결과. 유효/무효와 무효 사유를 가진다.
  (클릭, 규칙 버전)마다 하나다.
- **일별 광고 리포트(Daily Ad Report)**: 광고주에게 보여준 광고별·일별 수치. 날짜, 개정 번호, 상태(잠정/
  확정), 적용 규칙 버전, 유효·무효 클릭 수, 보정 사유를 가진다. 확정 후에는 바뀌지 않는다.
- **분 단위 광고 집계(Minute Ad Aggregate)**: 광고별 1분 구간의 유효·무효 클릭 수. 판정에서 언제든
  다시 만들 수 있는 읽기 모델이며, 준실시간 조회와 상위 N개 조회의 근거다.
- **파이프라인 지표(Pipeline Metric)**: 단계별 처리량·지연·적체·중복 제거·격리 수. 운영 기록이며
  시각화 화면의 근거다.
- **격리 이벤트(Quarantined Event)**: 형식 오류나 재시도 한도 초과로 정상 처리하지 못한 이벤트.
  원본과 실패 이유를 보존한다. (도메인 엔티티가 아니라 운영 기록이다.)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 중복 전송과 일시 장애를 섞은 검증 시나리오에서, 저장된 클릭 수가 보낸 고유 클릭 수와
  100% 일치한다(유실 0건, 중복 저장 0건).
- **SC-002**: 시스템은 초당 10,000건의 클릭을 30분 동안 계속 받아도 유실 없이 저장하고, 지연이
  SC-009 목표 안에 머문다.
- **SC-003**: 클릭을 받은 사용자의 95%는 1초 안에, 99%는 2초 안에 랜딩 페이지로 이동한다.
- **SC-004**: 확정된 모든 일별 리포트에서 유효 + 무효 = 측정된 클릭 총수가 100% 성립한다.
- **SC-005**: 판정 사유별 검증 묶음에서 판정 결과가 기대값과 100% 일치한다.
- **SC-006**: 일별 리포트는 해당 날짜가 끝난 뒤 늦은 도착 유예 시간 + 1시간 안에 확정된다.
- **SC-007**: 광고주 조회의 95%는 1초 안에 결과를 받는다.
- **SC-008**: 다른 광고주의 데이터 접근 시도는 100% 거부된다.
- **SC-009**: 측정된 클릭의 95%는 2분 안에, 99%는 5분 안에 광고주 조회(최근 M분, 상위 N개) 결과에
  반영된다.
- **SC-010**: 시각화 화면의 단계별 수치는 실제 상태 변화를 5초 안에 반영한다.
- **SC-011**: 데모 시나리오를 실행하면 10초 안에 화면에 그 효과(중복 제거 증가, 적체 증가 등)가 나타나고,
  시나리오가 끝난 뒤 2분 안에 정상 상태로 돌아온다.
- **SC-012**: 모든 데모 시나리오가 끝난 뒤 대조식이 100% 성립한다(유실 0건, 중복 반영 0건).
- **SC-013**: 처음 보는 사람이 화면을 3분 안에 둘러보고 클릭이 거치는 단계와 중복·늦은 도착을 어떻게
  다루는지 설명할 수 있다.

## Assumptions

- 도메인 모델은 "광고 클릭 집계 · 경량 도메인 ERD" 문서(엔티티 6개)를 따른다. 캠페인·광고그룹 계층,
  과금, 전환, 노출 수 기반 지표(CTR)는 이번 범위 밖이다.
- 광고주·광고 정보는 미리 등록되어 있다고 가정하며, 이를 관리하는 화면·기능은 범위 밖이다.
- 노출은 이 시스템이 기록한다(광고 송출 자체는 범위 밖이고, 노출 사실을 받아 기록만 한다).
- 유예 시간은 두 가지다. 1분 집계 구간을 닫기 전 기다리는 짧은 유예(기본 15초)와, 노출 없음 판정
  확정·일별 확정에 쓰는 긴 유예(기본 24시간)다. 짧은 유예를 넘긴 클릭은 일별 확정 때 대조로 반영된다.
- 목표 처리량은 참고한 설계(하루 10억 클릭, 평균 초당 약 1만 건)의 평균치를 개인 프로젝트에 맞춰
  지속 처리량으로 잡았다. 피크 대응(초당 5만 건 수준)은 범위 밖이다.
- 시각화 화면은 포트폴리오용 데모다. 오너의 로컬 컴퓨터에서 띄울 때만 볼 수 있고, 합성 데이터로만
  돌아간다. 외부 공개·호스팅·배포와 그 비용은 범위 밖이다.
- 시각화 화면은 직접 만든 웹 화면으로 한다. 헌법 v1.1.0에 따라 웹 화면은 TypeScript로 작성하고,
  백엔드가 공개한 API·지표만 읽는다.
- SC-002(초당 10,000건)는 개발용 노트북 한 대의 로컬 데모 환경 기준으로 검증한다.
- 판정 규칙 파라미터의 기본값: 노출 유효기간 24시간, 재클릭 간격 10초. 봇 기기 정보 목록과 내부 IP
  목록은 설정으로 관리한다.
- 중복 클릭 판정에서 "직전 클릭"은 판정 결과와 관계없이 같은 노출에서 측정 시각상 바로 앞의 클릭이다.
- 광고주 시간대가 바뀌면 바뀐 이후 날짜부터 적용하고, 이미 확정된 과거 리포트는 다시 만들지 않는다.
- 광고주 인증은 표준 방식(토큰 기반)을 쓰며, 광고주 계정 가입·관리 기능은 범위 밖이다.
- 현재 다루는 데이터는 테스트·합성 데이터뿐이다. 실제 사용자 데이터를 받기 전에 헌법 원칙 IV를
  개정해 IP·기기 정보의 해시·마스킹과 보존 기간을 정한다.
- 처리 시각(수신 시각)은 도메인 엔티티에서는 뺐지만, 지연 측정(FR-023)과 늦은 도착 판단을 위해
  운영 기록으로는 남긴다.
